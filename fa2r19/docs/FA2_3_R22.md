# FA2.3 / R22 — Causal document-persistent 32K-addressed memory

Date: 2026-11-12  
Parent: one accepted PAL R18 checkpoint; FA2.2 R21 frozen gate at 1,000 updates.  
**Status: experimental R22 adapter, NOT promoted.**

## Architecture and invariance

R22 builds on R21's learned content-only copy selector without creating a second language model or resetting the original optimizer histories. The inherited R18 decoder, R18 long-memory query/key network, all original weights, and the original R21 optimizer/state are frozen for these tests. The new R22 adapter comprises three separate zero-initialized residual gates (recent/middle/far, 414 new parameters total).

All retrieval is drawn from the same document **strictly before** the evaluated local chunk. For a query at global token position `t`, admissible source values are `j <= t-65`, and all sourced values are `j < window_start` (the retrieval cache never reads the current window). The key is the two pieces preceding a source, and the query is the two pieces preceding the current target. This strict causal architecture was checked by perturbing the future suffix; the original logits are bit-identical at zero R22 gain.

Dense near memory covers 65–2,047 positions, middle compressed memory 2,048–8,191 at stride 8, and far compressed memory 8,192–32,767 at stride 32. A bounded exact-prefix index rescues skipped candidate positions, but only makes rescued slots visible for **that query's exact prefix**; an early implementation allowed a future query to influence the earlier shortlist and was caught by the causality regression test and corrected before these reported results. There is no claim that lexical two-piece matches are semantic embeddings.

The *underlying decoder is not trained on 32K-token recurrent contexts*; only the read-only preceding-document retrieval address space is extended to 32K. This is a substantial but limited long-context step.

## CPU training trajectory

- Stage A: 300 updates, 20 train book windows, 8 development and 8 historical test windows; train only R22's three gates.
- Stage B: restore Stage A weights **and its Adam moments**; add 700 updates to reach **1,000 cumulative R22 adapter updates**, 96 train windows and 16 development windows, persisted using a disk-backed cache to fit the 4 GiB CPU-memory cap. The selected candidate was checkpointed before historical test evaluation.
- The original R18 checkpoint (step 10,756), R21 learned state (1,000 steps), and all inherited optimizer histories remain immutable. No rejected candidate was promoted.

At the Stage B 120-chunk horizon, matched development BPB on 16 windows was **2.514956 R18**, **2.512992 R21**, **2.502711 R22**. The later frozen 8-window historical book-disjoint test was **2.399262 R18**, **2.398389 R21**, **2.388457 R22**. Non-space historical NLL went **4.381388 R18** → **4.378581 R21** → **4.356440 R22**. The 24-chunk short context was unchanged by the hard minimum R22 query position 192. Book-disjoint is not clean-new-book: these authors/books were consulted in previous PAL rounds.

- R18: 16/16 passed.
- R19: 12/12 passed.
- R22: 11/11 passed, including bit-exact zero residual, future-suffix noninterference, beyond-8K causal access, exact-prefix rescue, new gate gradients, unchanged accepted checkpoint SHA.
- Parent accepted SHA-256: `dd040106568786e7fbad2a880f4010635b626b51c3697e2ab08712905a2de91f` (121,882,910 bytes, **not** bundled in the small source archive).
- New R22 candidate adapter SHA-256: recorded in `MANIFEST_FA2_3.json`, approximately 31 KiB including its own Adam moments.
- Test corpus is NaNROUTER's manifest-verified book-disjoint split, but *not fresh to the broader PAL research effort*. The R22 experiment evaluated those books after development selection, not during the training update loop.
- A larger cached-data attempt exhausted RAM and two runs were interrupted by execution deadlines, but the successful 1,000-step parameter state was saved at the end of the training phase and separately evaluated read-only. Do not mistake an interrupted wrapper for an interrupted optimizer update after save.

## What is required for frontier trajectory

The reported gains are measurable but small, and BPB about 2.4 is not frontier-model quality. Crucially, no semantic paraphrase or multi-hop task has passed an acceptance gate. The next architectural changes should be **trainable longer query/key contextual encoders**, a **semantic multi-positive contrastive objective with adversarial hard negatives**, **multi-token/value-span readout** (not just a copied next-token ID), a **persistent state that carries across training windows**, and **scalable chunk-level indices with ANN/attention instead of rescoring thousands of slots**. Then train on dramatically more book tokens, measure throughput/scale trends, and evaluate untouched author/book splits plus genuinely compositional QA. Do not promote R22 merely on reused historical test wins.

## Reproduction

From the full original PAL R19 release ZIP (corpora and tokenizer included), overlay these archived R22 source files into `source/`, restore the FA2.2 R21 gate into `reports/`, and execute:

```bash
PYTHONPATH=source python source/test_r22_multiscale_memory.py .
PYTHONPATH=source python source/test_r18.py .
PYTHONPATH=source python source/test_r19.py --root .
# Reproduce training from a recovered stage-300 adapter checkpoint, with source-verified books:
PYTHONPATH=source python source/r22_cpu_longmemory.py --root . --steps 1000 \
  --train-windows 96 --dev-windows 16 --test-windows 16 --eval-every 50 \
  --resume-state reports/r22_multiscale_candidate_300.pth
# For the frozen accepted R22 candidate, without retraining:
PYTHONPATH=source python source/r22_frozen_postselection.py --root . --test-windows 8
PYTHONPATH=source python source/r22_horizon400.py --root . --windows 8
PYTHONPATH=source python source/r22_scale_ablation.py .
```

The full original R19 archive remains a separate authoritative recovery artifact in Library; the cumulative R20/R21/R22 source ZIP excludes the 121 MB model and large corpora intentionally. The R22 adapter `.pth` is *never* a replacement for the accepted PAL checkpoint.
