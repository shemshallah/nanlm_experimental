# FA2.2 R21 — Adaptive relevance-and-novelty gate (CPU trial)

- **Lineage:** FA2.1 / PAL R18 accepted unified checkpoint; no new base language model.
- **Accepted checkpoint SHA-256:** `dd040106568786e7fbad2a880f4010635b626b51c3697e2ab08712905a2de91f`.
- **Accepted checkpoint steps:** 10,756, unchanged.
- **Experimental extension:** one trainable 138-parameter relevance/novelty gate on inherited R18 key/query embeddings with R20 content-only candidate filtering.
- **Causal separation:** a query at t uses only preceding two tokens; memory values j <= t-65; conservative activation threshold t >= 192.
- **Train:** 1,000 cumulative gate-only CPU updates, resumed from accepted gate candidate at 300, using 24 windows from verified NaNROUTER Gutenberg training books; 8 dev long + 12 short dev windows.
- **Selection:** best gate selected strictly on development long BPB and non-space NLL. Historical book-disjoint test evaluated after selection; it has been used in prior PAL work and is **not** an untouched clean new-book result.
- **Inherited AdamW:** all original optimizer groups, weights and moments untouched; a separate 11 KB quarantined gate candidate saves its own optimizer for continued gate-only training. It is not an independent PAL model or an accepted release.

## Final matched metrics versus accepted R18

| Metric | Development delta (R21−R18) | Historical test delta (R21−R18) |
|---|---:|---:|
| Long-context bits/byte (lower is better) | -0.003190 | -0.000872 |
| Long non-space NLL (lower is better) | -0.006849 | -0.002807 |
| Long non-space top-1 (higher is better) | +0.002946 | +0.001051 |
| Short bits/byte | +0.000000 | +0.000000 |

**Decision: candidate NOT promoted.** BPB gain is small. The 192-token cutoff makes short windows identical to R18 by design. Neither paraphrase/semantic hard negatives nor two-hop downstream improvement has been demonstrated by this gate; pristine external-book evaluation and full legacy-prediction gates are still required.

## Reproduce locally

The latest full R19 release ZIP is required for checkpoint, tokenizer and nanrouter corpus; reconstruct from the 36 committed parts via `restore_fa2_checkpoint.py` only if using GitHub verifier. Unzip the complete trusted archive into one root and overlay `source/r21_*.py` and this document.

```bash
python source/r18_verify_lineage.py --root .
python source/test_r18.py .
python source/test_r19.py --root .
python source/test_r20_soft_admission.py .
python source/test_r21_relevance_novelty.py --root .
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 python source/r21_cpu_candidate.py \
 --root . --steps 1000 --train-windows 24 --dev-windows 8 --test-windows 8 \
 --short-windows 12 --long-span 120 --max-tokens 700 --eval-every 70
```

For an exact staged replay, run `--steps 300 --eval-every 30` first, then `--steps 1000 --eval-every 70 --resume-state reports/fa2_2_r21_gate_candidate.pth` with the same train/dev configuration. The report stores the best gate weights as JSON, and the 11 KB candidate stores corresponding Adam moments. Do not overwrite the inherited checkpoint with an R21 candidate until all gates pass.

## Known limitations

1. The inherited R18 decoder's own causal assumptions are relied on; this work tests only the incremental memory mechanism.
2. Semantic memory proposals are based on normalized two-token keys, not an independently validated semantic retriever.
3. Historical test metrics remain postselected research observations, not independent frontier performance claims.
4. O(context²) memory ranking is unsuitable for production 8k/32k/65k contexts without a sparse index.
