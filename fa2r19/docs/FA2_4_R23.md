# FA2.4 R23 — parallel 64-token context, multi-value, hard-negative training

Date: 2026-11-12. Branch: `fa2-r23-context64-parallel`. Status: **unpromoted experimental implementation**.

## Strict lineage

The single accepted PAL R18 checkpoint is unchanged: SHA-256
`dd040106568786e7fbad2a880f4010635b626b51c3697e2ab08712905a2de91f`.
FA2.2 R21 and FA2.3 R22 are both FROZEN; R22 remains the strongest prior
experimental adapter, not the accepted checkpoint. New trainable weights are
only an R23 reader which consumes the preexisting R22 logits. Adam moments for
R18/R21/R22 are retained byte-identically. New R23 Adam moments are saved in
the candidate, and may only be resumed with exactly matching parent hashes.

**No frontier-quality or held-out improvement is claimed until training and
the blind evaluation complete.** This change is architecture and test code,
not a newly accepted language model.

## Parallel experimental arms

The CPU workflow defines four independent, compute-matched candidates using
the same inherited checkpoint, corpus windows and initialization:

| Arm | Decoder loss | Multi-value contrastive | Paraphrase hard negatives |
| --- | --- | --- | --- |
| `context` | Yes | No | No |
| `value` | Yes | Yes | No |
| `semantic` | No | No | Yes |
| `joint` | Yes | Yes | Yes |

The four candidates do **not** become four accepted language models. Their
readout and embedding-space experiments independently determine which
features merit integration into ONE unified future checkpoint. Never average
their weights or reset the inherited optimizer.

### Reader: 4–64 contextual keys

R23 encodes the **preceding** 4, 8, 16, 32 and 64 tokens with separately
trainable query/key projections, attentive and mean pooling, and a learned
span mixture. It uses the frozen PAL piece embedding table, not pretrained
external encoders. The decoder receives a new exactly-zero-initialized
gated residual for migration safety.

### Eight-token stored value spans

Every candidate memory value contains up to 8 complete, historical tokens.
The readout produces offset-0 to offset-7 future token distributions.
For *causal next-token BPB*, only the offset-0 prediction at that query
position influences the decoder logits. Future offsets are **auxiliary**
supervision, never applied to positions earlier than the necessary context.
Contrastive value supervision supports lengths 1, 2, 4 and 8 with multiple
historical positives. The labels select positives **only inside the loss**;
they cannot alter candidate admission or inference scores.

### Adversarial semantic tests

The semantic arm reuses R19's controlled nonce-entity fact/query templates,
but trains the **same R23 query/key encoder** and two-positive InfoNCE ranking
against seven distractors. Development queries use withheld paraphrase forms
with nonce names distinct from training. Test is consulted after dev selection.
This is a **synthetic semantic probe**; passing it is not equivalent to
real-world semantic comprehension, multi-hop QA or open-domain reasoning.

### 32K document-persistent training

Source candidates are indexed from a previous window of the **same book**.
Three distance tiers remain: recent 65–2047, middle 2048–8191, far
8192–32768. Candidate ranking is jointly trained using LM, value, or
semantic gradients, and the index spans adjacent windows without clearing
the absolute document address space. Importantly, **the original decoder's
recurrent BPTT is not expanded to 32K tokens**. This qualifies as end-to-end
training *through the 32K-addressed memory reader*, not through 32K recurrent
language-model states. A genuine 32K backbone/state experiment remains an
additional research stage.

## Causality and provenance

- Memory key: only `tokens[j-64:j]`.
- Memory value: `tokens[j:j+8]` fully before the current window start.
- Query key: only `tokens[t-64:t]` (strictly before current target).
- Minimum distance: `t-j >= 65`; max distance 32768.
- Candidate shortlists combine 2-piece rescue, same-last-token distractors,
  and sparse historical anchors; rescue matches only the *current query*.
- Edited future suffixes must not alter prior read indices, keys or values.
- Zero R23 gain must reproduce frozen R22 logits bit-for-bit.
- The frozen R18/R21/R22 checkpoint hashes are rechecked after training.
- Exact original R19 ZIP digest is validated before deserialization.
- All four arms save their own optimizer continuation state.
- Historical NaNROUTER test books have already been examined during older PAL
  rounds. Fresh author/book evaluation remains mandatory for acceptance.

## Running

Source-only structural test (no model binary):

```bash
cd fa2r19/source
python test_r23_context64.py
```

For CPU training, the [R23 parallel workflow](../../.github/workflows/fa2-r23-parallel.yml)
requires a trusted HTTPS URL to the **exact original PAL R19 full release ZIP**,
not just a checkpoint: it contains tokenizer, book corpus/manifest and legacy
assets that are absent from the minimal GitHub source directory. GitHub itself
stores 36 accepted checkpoint chunks and the R21/R22 frozen adapter states.

From the Actions workflow's `workflow_dispatch` form, supply `archive_url`,
`steps` and `train_windows`. Four independent runner jobs will execute in
parallel. Candidate checkpoint and result JSON are *run artifacts*, not silently
written over the accepted model. Running with a blank URL performs the source
audit only. Repository source changes alone do not mean any CPU training has
been completed.

The development gate selects the best checkpoint within each arm. The
historical test is read once after freezing that candidate. Promotion requires
strict short/long NLL gates, blind book-disjoint plus author-disjoint results,
real paraphrase and multi-hop transfer, and preserved historical regressions.
