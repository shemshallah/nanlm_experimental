# Blackwell 600-second results (2026-11-18)

Hardware: **NVIDIA RTX PRO 6000 Blackwell Server Edition**, 94.97 GiB,
CUDA 13.2, `torch 2.11.0+cu130`, `torch_xla` unused.

## Measured runs

| Run | Steps | Tokens | Wall | Val BPB | Held-out test BPB | Test top-1 |
|---|---:|---:|---:|---:|---:|---:|
| WikiText-2, 600 s cap | 1,100 | 9,011,200 | 557 s | **0.5336** | **0.5183** | 71.55% |
| WikiText-2, 880-step schedule | 880 | 7,208,960 | 474 s | 0.8843 | 0.8576 | 54.84% |
| OOD Tiny Shakespeare | — | 337,118 eval | — | — | **4.4842** | 8.50% |
| WikiText-103 official test, transfer | — | 282,936 eval | — | — | **0.7905** | 59.63% |

The 600 s run used batch 16, ctx 512, LR 4e-4, bf16, no gradient
checkpointing, `--threads 8`, and the `kaggle10m_nomtp` preset. It finished
its 1,100-step schedule in 557 s with zero non-finite skips.

## The OOD result is the important number

The Tiny Shakespeare eval used the **same checkpoint and the same evaluator**
as the WikiText-2 test, with only the test corpus changed. It produced
**4.4842 BPB / 8.50% top-1**, worse than the ~3.59 BPB uniform baseline.
The model is not a general language model; the 0.518 WikiText-2 number is a
narrow Wikipedia/WikiText-2 fit.

This is consistent with the token budget: 9,011,200 tokens is **3.5 epochs**
over the 2,566,566-token train split. The T4 comparison ran 1.84M tokens
(0.72 epoch) and scored 1.5981 test BPB.

The WikiText-2 test split is document-disjoint by hash, and 32-token shingle
overlap with train is only **0.21%**, so this is not exact text leakage. It is
domain overfitting: the held-out documents are from the same small Wikipedia
article pool and share vocabulary/style with the 98% seen in training.

## WikiText-103 is not a leaderboard claim

The official WikiText-103 **test** transfer scored 0.7905 BPB / 59.63% top-1.
That is same-domain Wikipedia transfer, not a WikiText-103 benchmark:
the model was trained on WikiText-2, not WikiText-103 train. The 32-token
shingle overlap with the WikiText-2 train bin is 0.011%, but WikiText-2 is a
subset of the same Wikipedia source, so the domains are related.

A 5-minute WikiText-103 baseline was attempted on a 12 MB subset of the
official train split (2,484,865 train tokens) but the shared GPU was occupied
by another process using 74,369 MiB / 97,887 MiB and 100% utilization; the
job OOMed at step 1. No WikiText-103 training result is claimed.

A real WikiText-103 leaderboard attempt requires training on the WikiText-103
train split for a meaningful duration (hours, not five minutes) and evaluating
the official test split with the standard protocol. A 12 MB / 5-minute
baseline cannot support a leaderboard claim.

## What was optimized

- `v3_model.RMSNorm` and `concept_loop._RMSNorm` cast the weight to the
  autocast dtype and use `F.rms_norm`, removing fp32 promotion and the
  fused-kernel dtype warning.
- Concept segment pooling now uses a **row-local fixed-shape sort/scatter**
  on every device, removing `torch.unique` and `bool(any())` GPU syncs from
  every layer.
- Training skips the unique-based object histogram diagnostics; evaluation
  still computes them.
- CUDA compute capability >= 8 enables TF32 for residual fp32 work.
- Batch-size benchmarks: ~7.2k tokens/s at batch 4, ~13.8k at batch 16,
  ~15.4k at batch 32/64. The 600 s run used batch 16 for more optimizer steps.

## Reproduction

```sh
python z3/train_v3.py \
  --device cuda --amp --amp-dtype auto \
  --preset kaggle10m_nomtp \
  --corpus data/wikitext_bins/train.bin \
  --val-corpus data/wikitext_bins/valid.bin \
  --data-manifest data/wikitext_bins/manifest.json \
  --batch-size 16 --ctx 512 --lr 4e-4 \
  --steps 1100 --lr-total-steps 1100 \
  --eval-every 100 --eval-batches 2 \
  --max-seconds 600 --no-grad-checkpoint --threads 8 \
  --out runs/blackwell_600_full
```

OOD eval:

```sh
python z3/eval_domains.py \
  --checkpoint runs/blackwell_600_full/best.pt \
  --test-dir data/ood_shakespeare \
  --tokenizer layered --document-framing --sidecar --require-sidecar \
  --ctx 512 --batch-size 16 --device cuda \
  --out runs/blackwell_ood_shakespeare.json
```

The Molab checkpoints and JSONs are in `/marimo/z4_smoke/runs/`; they are
not committed to the repo.
