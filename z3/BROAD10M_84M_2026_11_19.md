# 84M no-MTP 10-minute continuation (2026-11-19)

The 84M model (`84,455,112` params) is the bit-equivalent no-MTP trunk
described in `BROAD20M_BALANCED_2026_11_19.md`. This run resumes the
68.8M-token checkpoint and trains for **10 wall-clock minutes** on the
955M balanced corpus.

## Run

| Field | Value |
|---|---|
| Parameters | 84,455,112 |
| Batch / ctx | 64 / 512 |
| Tokens this run | 12,320,768 |
| Total tokens | 81.1M |
| Wall time | 605.5 s (10m 05s) |
| Throughput | ~20.4k tokens/s |
| Optimizer | fresh AdamW (checkpoint weights preserved) |
| LR | 4e-4, time-based WSD, 600 s horizon, 30-step warmup |

Blackwell settings: chunked/checkpointed 64k cross-entropy, causal SDPA
fast path at `ctx <= window`, native GQA, bf16 autocast, TF32, fused
AdamW, dense MoE dispatch, `expandable_segments:True`, no gradient
checkpointing, 12 CPU threads.

Batch 128 was retested and still OOMs at 93.9 GB; batch 64 is the stable
maximum. `torch.compile` remains unusable (~48 s/step from recompiles).

## Conclusion

Stay on the **84M no-MTP** model. It is the same active trunk as the 115M
`nomtp` model, with 30.8M dead parameters removed, exact logits/gradient
parity, and a 338 MB checkpoint instead of 510 MB. At 81.1M tokens it is
slightly ahead of the 115M checkpoint on clean PTB. A true 115M model now
means widening the trunk, not re-adding MTP.
